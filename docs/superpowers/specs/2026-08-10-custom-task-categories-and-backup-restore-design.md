# 追加カテゴリ・バックアップ復元改善設計

作成日: 2026-08-10

対象バージョン: `mvp-1.5.0`

対象要件: F-005、F-006、F-008、F-014、F-017、F-018、NF-001、NF-004、NF-006、NF-008、NF-010、NF-012

## 1. 目的

変更不可のプリセットカテゴリを維持しながら、利用者がこの端末だけで使うタスクカテゴリを追加できるようにする。追加カテゴリはタスク化、タスク修正、タスク一覧の絞り込み、入力本文からの候補提示に反映する。

あわせて、JSONバックアップの復元が追加ではなく洗い替えであることを画面上で明確にし、別端末へ復元したときの通知予約再構築を、未整理の受信箱、メモ、対応中タスクまで一貫させる。

## 2. 確定事項

- 【確定】プリセットは `仕事 / 家 / 買い物 / その他` の4件とし、利用者は名称変更・削除・並べ替えできない。
- 【確定】追加カテゴリはアカウントではなく、この端末の設定として端末内だけに保存する。
- 【確定】追加カテゴリはJSONバックアップへ含めるが、通知APIへ送信しない。
- 【確定】追加カテゴリは最大10件、名前は前後空白を除いた1〜12文字とする。
- 【確定】プリセット名および有効な追加カテゴリ名との重複を拒否する。
- 【確定】上限10件は現在有効な追加カテゴリだけを数え、削除済みカテゴリと既存タスクだけに残る過去カテゴリは数えない。
- 【確定】削除した追加カテゴリは新規選択肢から外すが、そのカテゴリを持つ既存タスクの値は変更しない。
- 【確定】削除したカテゴリと同じ名前を再登録した場合は、再び有効な選択肢として扱う。
- 【確定】追加カテゴリ名が入力本文へ同じ表記で含まれる場合だけ候補提示する。読み仮名、類義語、表記揺れは推測しない。
- 【確定】候補提示は自動確定ではなく、利用者の選択を必要とする。
- 【確定】設定画面の折りたたみ式 `データ` カード内で、バックアップより前に追加カテゴリ設定を置く。
- 【確定】UIの配色、カード、余白、ボタン、保存結果表示は現行設定画面のトンマナを踏襲する。
- 【確定】復元は現在データへの追加ではなく、バックアップ内容による一括置換とする。
- 【確定】別端末への復元は移動ではなくコピーであり、バックアップ元端末のデータと通知予約を遠隔削除しない。
- 【確定】復元先端末の端末ID、Push資格情報、通知登録状態を維持し、復元データから匿名通知予約を再構築する。
- 【確定】複数画面、ドメインルール、保存形式を変更するため、版を `mvp-1.5.0` とする。

## 3. カテゴリのデータ設計

### 3.1 保存形式

`Settings` に有効な追加カテゴリ名を登録順で保持する。

```ts
interface Settings {
  // existing fields...
  customTaskCategories: string[];
}
```

`AppSnapshot.schemaVersion` は `8` へ更新する。バージョン7から8への移行では `customTaskCategories: []` を追加し、既存のプリセットカテゴリ値は変更しない。

Taskのカテゴリ値はプリセットだけに閉じた型から文字列へ拡張する。Task自身がカテゴリ名を保持するため、設定から削除された追加カテゴリも既存Task上に残る。削除済みカテゴリの別台帳や削除フラグは保持しない。必要な過去カテゴリは現在のTask集合から導出する。

### 3.2 入力検証

- 前後の空白を除去してから空文字、文字数、重複を検証する。
- 文字列中の空白は利用者が入力した名称の一部として維持する。
- 大文字・小文字、ひらがな・カタカナ、漢字・読み仮名を自動変換しない。
- 最大件数は保存済みと画面上の編集内容を合わせた有効件数で判定する。
- 1件でも不正なら設定全体を保存せず、現在の端末データを維持する。

### 3.3 削除後の参照

追加カテゴリを設定から削除しても、Task.categoryは変更しない。

- 新規タスク化・別タスクの編集: 削除済みカテゴリを選択肢へ出さない。
- そのカテゴリを持つタスクの編集: 現在値を `冷蔵庫（過去）` のように表示し、変更しないまま保存できる。
- タスク一覧の絞り込み: 現在のTask集合から過去カテゴリを導出し、`冷蔵庫（過去）` として選択できる。
- 同名再登録: 過去表記を外し、通常の有効カテゴリとして扱う。

## 4. 設定画面

### 4.1 配置

`設定 > データ` の開閉カード内を次の順とする。

1. カテゴリ
2. 区切り線
3. バックアップと復元
4. 端末データ削除

カテゴリ見出しの直下へ次の説明を表示する。

> タスクで使うカテゴリを、この端末だけに追加できます。プリセットは変更できません。

### 4.2 編集UI

```text
カテゴリ
タスクで使うカテゴリを、この端末だけに追加できます。
プリセットは変更できません。

プリセット（変更不可）
[仕事] [家] [買い物] [その他]

追加カテゴリ                         8 / 10件
[カテゴリ名を入力                  ] [追加]
[経費 ×] [冷蔵庫 ×] [家族 ×]

[カテゴリを保存]
```

- プリセットは削除操作のない静的タグとして表示する。
- 追加欄へ1件入力し、`追加` またはEnterで画面上の編集内容へ加える。
- 追加・削除は直ちに永続化せず、`カテゴリを保存` で一括確定する。
- 編集内容が保存済み状態と同じ場合は保存ボタンを無効化する。
- 保存中は二重操作を防止し、ボタン文言を `保存中…` にする。
- 保存成功、入力不正、保存失敗は保存ボタン直下へ表示する。
- 狭い画面ではタグを自然に折り返し、横スクロールを発生させない。

### 4.3 上限表示

追加カテゴリ見出しの右側へ `8 / 10件` のように常時表示する。

10件へ達した場合:

- `10 / 10件` を強調する。
- 入力欄と追加ボタンを無効化して退色する。
- `追加カテゴリは10件までです。追加するには、いずれかを削除してください。` と表示する。
- 削除予定にした時点で編集上の件数を減らし、入力を再開できるようにする。
- 削除予定を元に戻して再び10件になれば、入力を再度無効化する。

### 4.4 削除操作

追加カテゴリの `×` を押した時点では永続削除しない。

1. 対象タグを退色させて `削除予定` と表示する。
2. 同じ場所に `元に戻す` 操作を表示する。
3. そのカテゴリを持つ全Taskを集計する。
4. 使用中なら `「冷蔵庫」が付いたタスク: 3件（対応中2件、完了・アーカイブ1件）` と内訳を表示する。
5. `選択肢からは削除されますが、これらのタスクには残ります。` と説明する。
6. `カテゴリを保存` で削除を確定する。

確認ダイアログは使用しない。削除予定、元に戻す、明示保存の三つを誤操作防止境界とする。Taskと操作履歴は削除しない。

## 5. タスク画面への反映

### 5.1 選択肢

タスク候補画面とタスク修正画面は次の順で表示する。

1. カテゴリなし
2. プリセット4件
3. 有効な追加カテゴリを登録順
4. 編集対象Taskだけが持つ削除済みカテゴリ

### 5.2 一覧の絞り込み

タスク一覧のカテゴリ絞り込みは次を含める。

- すべて
- プリセット4件
- 有効な追加カテゴリを登録順
- Taskに残っている削除済みカテゴリを名称順で `（過去）` 表示

対応中、完了、アーカイブ、すべての各状態で同じカテゴリ条件を利用できる。

### 5.3 候補提示

入力本文 `冷蔵庫の豆腐` と追加カテゴリ `冷蔵庫` は一致し、`冷蔵庫` を候補提示する。`れいぞうこのとうふ` は一致しない。

候補決定順は次のとおりとする。

1. 本文へ同じ表記で含まれる有効な追加カテゴリを抽出する。
2. 複数一致時は名称が長いものを優先する。
3. 同じ長さなら設定の登録順を優先する。
4. 追加カテゴリが一致した場合は、既存プリセットの簡易推測より追加カテゴリを優先する。
5. 追加カテゴリが一致しない場合だけ、既存プリセット候補を使う。

## 6. バックアップと復元

### 6.1 表示文章

バックアップ説明では、追加カテゴリを含む端末設定が対象であり、Push資格情報と有効なサーバー通知予約を含めないことを示す。

復元ファイルの確認後、確定ボタンの前へ次の趣旨を表示する。

> 復元は現在のデータへの追加ではありません。バックアップの記録・タスク・設定・履歴ですべて置き換わります。

別端末での利用について次を表示する。

> 別端末への復元はデータのコピーです。元の端末のデータと通知は残ります。通知の登録情報はコピーせず、復元先端末の設定を使います。

実行ボタンは現在の `この内容で置き換える` を維持し、ファイル選択だけでは保存しない。

### 6.2 復元処理

復元は次の順で行う。

1. 形式、schemaVersion、チェックサム、ID、参照、日付、カテゴリ設定を保存前に検証する。
2. 復元先端末のDeviceStateとPush資格情報を維持する。
3. 復元先端末に残る既存ReminderMapを取消Outboxへ変換する。
4. バックアップの記録、タスク、設定、履歴を一括置換する。
5. 復元時点の端末時刻と復元設定のタイムゾーンで、対応中Taskの次回確認・期限通知を再計算する。
6. 最古の未整理Captureを基準に、受信箱の全体通知系列を再構築する。
7. 最古のメモを基準に、メモ見直し通知系列を再構築する。
8. ローカルSnapshotを1回だけ保存する。
9. 通知Outboxを1回だけ同期する。

同じバックアップを再度取り込んでも、Capture、Task、履歴を追加・複製しない。復元操作履歴と、復元時点に再計算した通知予約だけを現在状態へ合わせる。

### 6.3 完了表示

- ローカル置換と通知同期が成功: `データを復元しました。通知への反映も完了しました。`
- ローカル置換は成功、同期だけ失敗: `データを復元しました。` と `通知への反映は送信待ちです。`
- 保存前検証または保存が失敗: 元Snapshotを維持し、理由を操作箇所へ表示する。

## 7. アーキテクチャ境界

- カテゴリの正規化、上限、重複、削除影響件数、候補順位はdomain層で扱う。
- 画面コンポーネントは `localStorage` を直接呼ばず、`AppRepository` とapplication serviceを経由する。
- カテゴリ保存はSnapshot全体を1回だけ保存し、部分保存を残さない。
- カテゴリ変更だけでは匿名通知予約を変更しない。
- 復元後の通知再構築は既存の通知Outbox application adapterへ委譲し、画面からHTTP APIを直接呼ばない。
- 通知APIへ送信できる項目は端末識別子、通知予約識別子、予定時刻、通知種別、繰り返し周期だけとし、カテゴリ名、Task本文、復元件数を送らない。

## 8. エラー処理

| 状況 | 表示・挙動 |
|---|---|
| 空文字 | 追加せず、入力欄直下へ理由を表示 |
| 13文字以上 | 追加せず、12文字以内を案内 |
| プリセット・追加カテゴリと重複 | 追加せず、登録済みであることを表示 |
| 10件到達 | 入力と追加を無効化し、削除が必要と事前表示 |
| カテゴリ保存失敗 | 保存済みSnapshotを維持し、編集内容は画面上に残す |
| 復元ファイル不正 | 現在データを変更せず、理由を表示 |
| 復元保存失敗 | 現在データを維持し、再試行可能にする |
| 復元後通知同期失敗 | 復元済みデータを維持し、Outboxを送信待ちとして表示 |

## 9. テスト

### 9.1 Domain

- schemaVersion 7から8へ空の追加カテゴリを移行する。
- 追加、前後空白除去、登録順を検証する。
- 空文字、13文字以上、プリセット重複、追加カテゴリ重複、11件目を拒否する。
- 削除しても既存Task.categoryが残る。
- 削除済みカテゴリの全Task件数と、対応中・完了・アーカイブ内訳を返す。
- 同名再登録で通常カテゴリへ戻る。
- 本文への完全な部分文字列一致、表記違い、複数一致、同長時登録順を検証する。
- 追加カテゴリ候補がプリセット簡易候補より優先される。
- 復元で未整理、メモ、対応中Taskの通知系列を一度だけ再構築する。
- 同一バックアップ再読込でエンティティが重複しない。

### 9.2 Web

- データカードを開くと、カテゴリがバックアップより先に表示される。
- プリセットに削除操作がない。
- 追加、削除予定、元に戻す、保存結果を表示する。
- `10 / 10件` で入力と追加が無効になり、削除予定で再び有効になる。
- 使用中カテゴリの全件数と状態別内訳を表示する。
- 保存失敗時に編集内容を維持する。
- タスク化、編集、一覧絞り込みへ有効カテゴリを表示する。
- 削除済みカテゴリを既存Taskと一覧絞り込みで `（過去）` 表示する。
- 洗い替えと端末間コピーの説明を表示する。
- 復元成功と通知送信待ちを区別する。

### 9.3 E2E・品質ゲート

- スマートフォン幅でカテゴリ追加、タスク化、絞り込み、削除、既存Task保持を確認する。
- PC幅でデータカード、タグ折り返し、選択肢を確認する。
- バックアップを書き出し、別browser contextへ復元して追加カテゴリとTaskを確認する。
- 同じバックアップを再読込して件数が増えないことを確認する。
- 通知契約テストでカテゴリ名とTask本文がHTTP本文、ログ、Push payloadへ出ないことを確認する。
- 単体、結合、E2E、lint、型検査、ビルドを実行する。
