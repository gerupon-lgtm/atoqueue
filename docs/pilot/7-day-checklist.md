# 7日間パイロット・チェックリスト

対象 URL は `https://atoqueue.sikumilab.com`。公開 staging は作らず、承認済みの本番 URL だけを使う。参加者は端末内データを必要に応じて JSON バックアップし、サーバーへ利用分析を送らない。集計は各参加者の書き出し JSON と本人のメモから行う。タスク本文や Push endpoint をこの記録へ転記しない。

## 開始前

- [ ] 日付、参加者識別子（氏名ではない）、端末、OS、ブラウザ、PWA インストール状態を [結果テンプレート](result-template.md) に記録した。
- [ ] 通知は任意であり、拒否・非対応時も今日の確認を使えることを説明した。
- [ ] 通知を使う端末では、許可、汎用通知、通知クリックから今日の確認への遷移を確認した。
- [ ] ローカル JSON を 1 回書き出し、復元は参加者が同意した場合だけ実施することを説明した。
- [ ] 通信を切ってキャプチャ、受信箱、今日の確認の基本操作を確認した。

## 毎日（1〜7日目）

各日の終了時に、端末内の画面または JSON から数を転記する。空欄ではなく `0`、`未実施`、`不明` のいずれかを使う。

| 日  | キャプチャ件数 | 自己申告の記録漏れ | 受信箱を処理した件数 | 今日の確認: 開始 / 完了 | レベル2/3の解決: 完了 / 再設定 / アーカイブ | 通知観測（端末別） | 摩擦・不具合メモ |
| --- | -------------- | ------------------ | -------------------- | ----------------------- | ------------------------------------------- | ------------------ | ---------------- |
| 1   |                |                    |                      |                         |                                             |                    |                  |
| 2   |                |                    |                      |                         |                                             |                    |                  |
| 3   |                |                    |                      |                         |                                             |                    |                  |
| 4   |                |                    |                      |                         |                                             |                    |                  |
| 5   |                |                    |                      |                         |                                             |                    |                  |
| 6   |                |                    |                      |                         |                                             |                    |                  |
| 7   |                |                    |                      |                         |                                             |                    |                  |

通知観測には、端末、予定時刻、表示時刻、表示なし、遅延、クリック遷移結果、OS/ブラウザの制約を記す。表示された通知は `あとキュー` / `確認したい項目があります` の汎用文であり、タスク本文を含まないことを確認する。

## 各機能の keep / change / remove 判断

7 日目に、すべての機能 ID へ 1 つの判断と根拠を記入する。`remove` は要件の棄却条件と比較し、通知機能を外す場合もアプリ内の今日の確認を代替として確認する。

| ID    | 確認観点                                 | 判断（keep/change/remove） | 根拠・次の対応 |
| ----- | ---------------------------------------- | -------------------------- | -------------- |
| F-001 | PWA起動・インストール                    |                            |                |
| F-002 | 一文キャプチャ・下書き・保存完了         |                            |                |
| F-003 | ローカル保存・オフライン基本操作         |                            |                |
| F-004 | 受信箱と1件ずつの整理                    |                            |                |
| F-005 | ルール候補（自動確定しない）             |                            |                |
| F-006 | Captureの不要・Taskの完了/アーカイブ管理 |                            |                |
| F-007 | 今日/明日/今週/日時/期限なし             |                            |                |
| F-008 | 期限未設定の再確認と週次抑制             |                            |                |
| F-009 | 今日の確認を1件ずつ進める                |                            |                |
| F-010 | 前のタスク・結果/一覧からの修正          |                            |                |

## 完了判定

- [ ] 7 日分のキャプチャ件数、記録漏れ自己申告、受信箱処理件数を集計した。
- [ ] 開始/完了した今日の確認と、レベル 2/3 を完了・再設定・アーカイブした件数を集計した。
- [ ] 通知の観測を端末ごとに分け、通知が届かない場合にもアプリ内フローが使えたか記録した。
- [ ] すべての F-001〜F-018 に keep/change/remove を記入した。
- [ ] 次のリリースへ持ち込む変更、MVP から外すもの、追加検証が必要なものを分けた。
