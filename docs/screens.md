# あとキュー（仮称）画面設計

## 1. 画面設計原則

- 最初の記録を最短にし、整理は後段へ分離する（F-002,F-004）。
- 主要操作は親指で押しやすい高さ44px以上とする（NF-012）。
- 色だけで状態を伝えず、文言とアイコンを併用する（NF-012）。
- 「今日の確認」は1画面1件とし、その場で処理を決められる選択肢を出す（F-012,F-014）。
- 通知許可は価値説明後の能動操作で要求し、初回起動時には要求しない（F-013,NF-005）。
- オフライン中も記録・整理・確認は使え、通知同期だけを送信待ちにする（F-003,NF-002）。
- 各画面のカード・入力欄・ボタンは設定画面と同じ、明るい背景、濃緑の主要操作、角丸の入力欄というトーンで統一する（NF-012）。

## 3. 共通ナビゲーション

### 3.1 スマートフォン

下部ナビゲーションを使用する。ナビゲーションはセーフエリアを避けたフローティングフッタとして画面下部に固定し、本文スクロール中も常に操作できる。本文領域はフッタに隠れない余白を確保する。アプリ全体は Kosugi を基本書体とする。ナビゲーション記号は線幅 `2.5` のSVGを用い、小さい画面でも識別できる太さにする。

| 項目   | 遷移先      | バッジ                     |
| ------ | ----------- | -------------------------- |
| 記録   | `/`         | なし                       |
| 受信箱 | `/inbox`    | 未整理件数                 |
| 今日   | `/today`    | 本日対象件数               |
| タスク | `/tasks`    | 期限超過件数               |
| 設定   | `/settings` | 通知同期エラー時のみ点表示 |

### 3.2 PC

左側ナビゲーションとし、入力領域の最大幅は640px、一覧領域は960pxとする（【想定】）。キーボード操作で主要ボタンへ到達でき、フォーカス表示を消さない。

## 4. S-001 クイック入力

### 4.1 表示要素

- 見出し: 「あとで思い出したいことは？」
- 1つのテキスト入力欄
- 主ボタン: 「保存して戻る」
- 補助表示: 受信箱の未整理件数
- 保存後メッセージ: 「保存しました。いまの作業に戻って大丈夫です」
- 初回だけの案内: 通知タイミングは設定で変えられること、通知許可は設定画面の能動操作で行うこと、保存した記録は受信箱でタスクにできること

通知設定済みの端末では入力欄に起動直後のフォーカスを置く。未設定端末では、上部の通知案内を先に表示し本文欄へ自動フォーカスしない。期限、カテゴリ、重要度は表示しない。

保存操作行は左に「保存して戻る」、右に端末内設定のチェック「Enterで登録」を一行で置く。初期値はONで、ONではEnterで保存・Shift+Enterで改行、OFFではEnterで改行して保存ボタンで登録する。

### 4.2 状態

| 状態       | 表示・動作                                                                     |
| ---------- | ------------------------------------------------------------------------------ |
| 初期       | 空欄、保存ボタン無効                                                           |
| 入力中     | 300ms後に下書きをローカル保存                                                  |
| 保存成功   | 入力を消し、完了メッセージを表示                                               |
| 保存失敗   | 入力を残し「端末に保存できませんでした。空き容量を確認して再試行してください」 |
| オフライン | 通常どおり保存。通信警告は不要                                                 |

### 4.3 キーボード

- PC: `Ctrl+Enter` / `Cmd+Enter` で保存
- `Esc` では入力を消さない

## 5. S-002 受信箱

`未整理` と `メモ` を切り替える。未整理キャプチャは新しい順に表示し、1件ごとに次の操作を直接出す。

- 「タスクかも」→ S-003
- 「メモ」→ 分類して一覧から除外
- 「不要」→ 不要として分類
- 本文編集

一括自動確定は提供しない。ルールによる候補判定ができる場合は「タスク候補」ラベルだけを付け、利用者の選択を待つ。

本文編集と「メモ」「不要」の保存操作は、同時実行時に古い保存状態で上書きしないよう、画面内で直列化する。

空状態: 「未整理のメモはありません。思いついたらすぐ記録できます」

メモ一覧は `note` に分類した記録を古い順に本文と登録日時で表示する。各項目からタスク化または不要化できる。通知は各項目ではなくメモ一覧全体に対してだけ予約する。

## 6. S-003 タスク候補確認

### 6.1 初期表示

- 元の一文
- 編集可能なタスク名
- 候補カテゴリ（未選択可）
- 期限の選択肢
  - 今日
  - 明日
  - 今週中
  - 日付を選ぶ
  - 期限なし
  - まだ決めない
- 主ボタン: 「タスクにする」
- 補助ボタン: 「メモにする」「受信箱へ戻る」

初回入力の軽さを損なわないため、この画面は保存直後に強制表示しない。

実装済みの候補規則は端末内だけで動作する透明な最小ルールとする。本文に含まれる `今日`、`明日`、`今週中` は期限候補に、買い物・仕事に関する限定キーワードはカテゴリ候補に、日付表現を除いた本文はタイトル候補にする。候補は編集可能な初期値であり、保存状態を変更しない。規則にない日付表現は利用者が「日付を選ぶ」で指定する。

### 6.2 期限意味

| 選択         | 保存値                                                                                                       |
| ------------ | ------------------------------------------------------------------------------------------------------------ |
| 今日         | 当日。時刻を指定した場合はその端末ローカル時刻、未指定は23:59（【確定】）                                    |
| 明日         | 翌日。時刻を指定した場合はその端末ローカル時刻、未指定は23:59（【確定】）                                    |
| 今週中       | 次の日曜。時刻を指定した場合はその端末ローカル時刻、未指定は23:59（【確定】）                                |
| 日付を選ぶ   | 選択日。任意の時刻を追加でき、未指定は23:59（【確定】）                                                      |
| 期限なし     | `dueMode="none"`。期限設定の再確認を停止し、次の日曜18:00の通常週次見直しへ回す。日曜18:00以降なら翌週とする |
| まだ決めない | `dueMode="unset"`、3日後に再確認                                                                             |

過去日を「日付を選ぶ」で指定した場合は、保存前に確認を表示する。キャンセル時は候補画面の入力値を保持する。

期限はクイック入力時には必須・入力対象にせず、受信箱から「タスクにする」を選んだ候補確認画面で任意に選ぶ。この画面には日付選択と時刻入力を表示し、時刻を空欄にした場合は23:59として保存する。

## 7. S-004 今日の確認

### 7.1 ヘッダー配置

見出し「今日の確認」は他画面と同じ左揃えとし、右側に矢印なしの「前のタスク」操作を置く。「前のタスク」は先頭では無効、2件目以降に有効にする。カード直前の右側に `3 / 8` の進行件数を置く。PCでは見出し・操作・進行件数・カードを同じ最大幅のコンテナに収め、画面端へ分散させない。戻るボタンは44px以上の押下領域を保ちつつ、1行で収まる控えめなサイズとする。

### 7.2 タスクカード

- 放置レベルに応じた声掛け
- タスク名
- 期限状態（端末タイムゾーンのローカル日付・時刻）
- 経過情報（例: 「期限から3日」）
- 操作ボタン

### 7.3 声掛け

| レベル | 例                                                                 | トーン       |
| ------ | ------------------------------------------------------------------ | ------------ |
| 0      | 「これ、いつやるかだけ決めておきますか？」                         | 軽い提案     |
| 1      | 「次に動ける日を決めると、忘れずに済みそうです」                   | 行動を具体化 |
| 2      | 「少し時間が経っています。今日やるか、日付を変えましょう」         | 選択を絞る   |
| 3      | 「このまま残すより、残すかどうかを決めましょう」                   | 判断を促す   |
| 4      | 「このまま残すより、完了・新しい期限・不要のどれかを決めましょう」 | 決着を促す   |

レベル3の文面は、F-011の段階定義に合わせて追加した【想定】であり、7日間試用で調整対象とする。

責める表現、人格評価、過度な緊急感は使わない。

### 7.4 操作

| 操作         | 結果                             | 次画面     |
| ------------ | -------------------------------- | ---------- |
| 完了         | 完了日時を記録、通知取消         | 次のタスク |
| 今日やる     | 期限を当日23:59へ変更            | 次のタスク |
| 日付を変える | 日付選択シートを開き更新         | 次のタスク |
| 期限なし     | `dueMode="none"`                 | 次のタスク |
| 今回は閉じる | 見送り回数を加算し次回確認を計算 | 次のタスク |
| 不要         | アーカイブ、通知取消             | 次のタスク |
| 前のタスク   | 直前のタスク表示へ戻る           | 同画面     |

二段階確認は原則行わない。前のタスクへ戻った場合は、直前に選んだ結果を表示し、別の操作を選ぶと新しい履歴を追加して状態を上書きする。破壊性が高い「不要」も履歴から再開できるため確認ダイアログを出さない（【想定】）。

未回答のまま移動する「次のタスク」ボタンは置かない。各回答を保存した後にのみ次のタスクへ自動で進み、未回答のタスクを確認漏れにしない。操作ボタンはスマートフォンでは2列同幅・48px以上・文字中央揃えとし、完了は淡緑、今日やるは淡い橙、日程変更は淡青、期限なしは淡灰、見送りは淡い砂色、不要は淡赤で補助的に区別する。押下中・保存中は対応する濃色と白文字へ切り替える。色だけに依存せず、操作名を常に表示する。

### 7.5 対象順

1. 期限超過が長い
2. 放置レベルが高い
3. 当日期限
4. 期限未設定の再確認時刻到来
5. 通常の再確認時刻到来
6. 作成が古い

同順位は `createdAt` 昇順とする。

### 7.6 空状態

「今日確認するものはありません。記録したことは受信箱やタスク一覧からいつでも見直せます」

## 8. S-005 今日の確認結果

- 完了、期限変更、期限なし、見送り、不要の件数
- 処理したタスク一覧と現在状態
- 各行の「修正」リンク → S-007
- 「タスク一覧を見る」
- 「記録へ戻る」

当日の全件確認後でも能動的に修正できることを明示する。戻る操作によるセッション再開ではなく、タスク詳細から新しい操作として記録する。

## 9. S-006 タスク一覧

### 9.1 タブ

- 対応中
- 完了
- 保管

### 9.2 絞り込み

- 期限超過
- 今日
- 期限未設定
- 期限なし
- カテゴリ

既定順は「次回確認時刻が早い順、期限が早い順、作成が古い順」。本文とタイトルの部分一致検索を端末内で行う（【想定】）。

各行に端末内のタスク登録日時を表示する。

絞り込みはスマートフォンで状態・期限・カテゴリを2列、検索を全幅のコンパクトな区画にまとめる。各タスク行はタイトル、期限状態、期限日時（ある場合）、登録日時を詰めて表示する。完了タブには、詳細画面の「再開」で対応中へ戻せることを明示する。

## 10. S-007 タスク詳細

- タスク名
- 元のメモ
- 登録日時（端末のタイムゾーンで表示）
- 状態
- 期限状態と期限（端末タイムゾーンのローカル日付・時刻で表示）
- カテゴリ
- 次回確認予定（期限と異なる場合のみ表示）
- 放置レベルの根拠
- 操作履歴（端末のタイムゾーンで表示）

操作: 内容を保存（タイトル・カテゴリのみ）、期限を保存（日付・時刻のみ）、期限なしにする、完了、再開、今回閉じる、不要。見出し「タスクを修正」の右には矢印なしの「タスク一覧」ボタンを置く。内容と期限は別の区画に配置し、保存対象を混同させない。各操作は44px以上の同一高さにし、内容保存・再開は全幅1本、期限操作は同幅2本、状態操作は同幅3本で配置する。幅360px未満では状態操作を同幅2本と全幅1本へ切り替え、押しやすさを保つ。完了済みタスクはS-006の完了タブから開き、「再開」で対応中に戻せる。

概要は登録日時・状態・期限・放置理由を詰めた一行単位の表示とし、期限と同じ次回確認予定は重複表示しない。期限編集は、日付（8桁の数字を入力すると `YYYY/MM/DD` で表示）と、時刻を有効化した場合の時刻（4桁の数字を入力すると `HH:MM` で表示）を各一行で扱う。各入力欄の横には8pxの余白を置き、44px正方形の独立した日付・時刻ピッカーボタンを置く。時刻を有効にするチェックは22px程度の標準サイズ・緑色とし、行全体を44px以上のタップ領域にする。時刻を有効化しない場合は設定の既定時刻を用いる。内容保存は淡緑、期限保存は淡青、期限なしは淡灰、完了は淡緑、後回しは淡い砂色、不要は淡赤とする。

保存時に通知予約を再計算する。同期できない場合でもローカル変更は成功とし、「通知の更新を送信待ちにしています」と表示する。

## 11. S-008 設定

### 11.1 通知

通知未設定時:

1. 「アプリを閉じていても、確認時刻を知らせられます」
2. 「タスク内容は通知サーバーへ送りません」
3. ボタン「通知を設定する」
4. ボタン押下後にOS許可を要求

S-001「記録」でも、通知設定を一度も実行していない端末では、保存欄の前に同じ「通知を設定する」ボタンを一時表示する。ここでの押下は設定画面へ移動するだけでなく、OS許可を含む通知設定を実行する。結果（許可・拒否・未対応・失敗）を表示した後は、この一時ボタンを消す。通知の再設定はS-008から行う。

通知設定済み時は、端末全体に適用する数値入力「初回通知まで（分）」「期限前通知（分）」、コンボボックス「受信箱の再通知」（しない／ゆっくり／気づかせる）と「メモの棚卸し」（しない／毎週／毎月）、日付だけの期限へ使う既定時刻、保存操作を表示する。頻度コンボを変更した直後は琥珀色の枠線と「変更を保存してください」で未保存を示し、保存後は緑の枠線と「現在この頻度で再通知します」を表示する。選択だけでは予約を変更せず、保存時に古い匿名全体予約を取消して組み直す。通知タイミングは内側のカード枠を使わず、設定画面の共通余白に直接配置する。各入力はラベルと単位（分後・分前）を1行にまとめ、数値欄を右側に置く。既定時刻は4桁の数字を入力すると`HH:MM`で表示し、8pxの余白を置いた44px正方形の時計ボタンからネイティブ時刻ピッカーも開ける。すべての手入力欄はタップ時に内容を全選択し、時刻・分数のラベルと数値は本文より少し大きく表示する。保存ボタンは左端を通知設定ボタンと揃える。保存操作と端末の「通知を設定する」操作の間には罫線と余白を置き、役割の異なる操作であることを明確にする。初期値は各60分と23:59、受信箱は「ゆっくり」、メモは「毎週」で、保存時は有効タスクと匿名全体予約を再計算する。端末登録済みならその状態を表示する。タスク本文・期限内容は表示・送信しない。

設定画面には、利用中のIANAタイムゾーンとUTCオフセットを表示する。期限・通知時刻はこの端末設定を基準にし、保存時はUTCへ変換する。配送サーバーが対象を確認する周期は最大5分であり、OSの省電力設定や通信状態により通知到達時刻は前後しうることを説明する。

スマートフォン向けに、端末登録の実行、ブラウザまたはインストール済みPWAの通知許可、電池最適化・集中モードの確認を案内する「スマホで通知が来ないとき」セクションを置く。

拒否時は再要求を連打せず、ブラウザ設定から変更する案内を出す。未対応ブラウザでは、アプリ起動時の今日の確認が利用できることを案内する。

### 11.2 データ

- 「JSONバックアップを書き出す」
- 「JSONバックアップから復元」
- 復元前の件数差分と置換確認

### 11.3 情報

- アプリ名
- バージョン
- 保存方式: 「この端末内」
- 同期状態: 「端末間同期はMVPではありません」
- 表記: `© 2026 SIKUMI LAB`

## 12. 通知からの遷移

Push payloadに含まれる匿名 `reminderId` をService Workerが `/today?reminder=<id>` へ渡す。アプリ起動後に端末内マップで対象タスクを解決する。

| 状態                 | 遷移                           |
| -------------------- | ------------------------------ |
| 対象タスクが有効     | 対象を先頭にした「今日の確認」 |
| 対象が完了・削除済み | 通常の「今日の確認」           |
| ID解決不可           | 通常の「今日の確認」           |
| データ読込失敗       | 復旧案内                       |

OS通知文面は「確認したい項目があります」のような汎用文にする。同じ端末で近接する通知は `tag="atoqueue-review"` により集約される可能性を許容する。

## 13. エラー・回復

| 状況                 | 利用者向け表示                       | 回復                               |
| -------------------- | ------------------------------------ | ---------------------------------- |
| localStorage容量超過 | 「端末に保存できませんでした」       | JSON退避、不要データ整理、再試行   |
| データ破損           | 「保存データを読み取れません」       | 破損JSON退避、バックアップ復元     |
| 通知API一時失敗      | 「通知の更新を送信待ちにしています」 | オンライン復帰・アプリ起動時に再送 |
| 通知購読失効         | 「通知を再設定してください」         | 設定画面で再購読                   |
| 復元ファイル不正     | 「このファイルは復元できません」     | 元データを保持、理由表示           |

## 14. E2E受け入れシナリオ

1. オフラインで一文を保存し、再読込後も受信箱に残る。
2. キャプチャをタスク候補にしても、確定操作まではタスクにならない。
3. 期限を「まだ決めない」にすると3日後の再確認対象になる。
4. 同じ期限未設定タスクを3回見送ると週次確認へ移る。
5. 複数タスクを順に処理し、右上の矢印なし「前のタスク」で直前へ戻って修正できる。
6. 全件確認後、結果画面から任意タスクを修正できる。
7. 期限超過タスクを完了、再設定、不要のいずれかで処理できる。
8. 通知許可を拒否しても、アプリ起動時の確認は使える。
9. Push通知から対象タスクまたは今日の確認を開ける。
10. JSONバックアップと復元でタスク・メモ・履歴が一致する。

## 15. 要確認事項

- 【要確認】「不要」を確認なしで即時アーカイブし、詳細から再開可能とする体験でよいか
- 【確定】今日・明日・今週中・日付指定では任意の期限時刻を入力でき、空欄は23:59とする
- 【要確認】受信箱に本文編集を置くことで選択肢が増えすぎないか

## 16. 共通UIの補足

- 各画面の本文領域の先頭に、控えめな文字サイズ・色の「あとキュー」を共通表示する。画面見出し、本文、ナビゲーションの文字サイズは変更しない。
- タップ操作は44px以上を保つ。タスク詳細の「タスク一覧に戻る」も同じ基準とし、見出しとの余白や横幅は変えない。
- 受信箱の「タスクかも」「メモ」「不要」は等幅の3列で並べる。幅360px未満では、最後の「不要」を次行の全幅にして文字が窮屈にならないようにする。
- タスク候補の「タスクにする」は全幅の主操作、「メモにする」と「受信箱へ戻る」は等幅の補助操作として並べる。
- 設定の「スマホで通知が来ないとき」は初期状態で折りたたみ、必要なときだけ展開する。端末データ削除の確定・取消は同じ幅で表示し、危険操作だけを淡い赤系で区別する。
