# テンパリスト起動URL連携 実機確認記録票

作成日: 2026-09-11。対象要件: F-020。

## 1. 確認の境界

### 2026-09-12 利用者の実機報告

- Androidからは正しく連携できたとの報告。OS・ブラウザの版、受信側起動中/終了時の個別条件は未記録のため、下記マトリクスの全条件成功へは読み替えない。
- iOSホーム画面のあとキューから開いたテンパリスト内には作成リストが蓄積されるが、普段のホーム画面版・ブラウザ版テンパリストには現れない。
- iOSのブラウザ版あとキューからはブラウザ版テンパリストへ連携され、ブラウザで再度開いてもリストが残るとの報告。
- 運用方針はAndroid、およびiOS/iPadOSの通常ブラウザ内に限定。1.29.0では送信側のOS判定とstandalone/fullscreen判定でホーム画面版の連携を停止する。端末データの自動移行・削除は行わない。
- 正式アイコン `NEテンパリスト/assets/icon.svg` を受領。連携済の控えめな14px表示に採用する。
- 制限・配置修正後の実機再確認は未実施。利用者報告と自動テスト結果は区別する。

- 本番向けUIは「タスク → チェックリストにする → 合成Task2件を選択 → 内容を確認 → 内容を確定 → テンパリストで開く」。ローカル保存後に `location.assign` で遷移する。実機ではこの経路を使い、実際の利用者Task本文は使わない。
- `/dev/tempalist-link` は開発時だけの先行試験画面。固定UUID・固定2項目の通常anchorで比較できるが、本番ビルドには含まれない。製品UIの保存後起動やOS動作をこの試験画面だけで確認済みにしない。
- 受信側で作成前確認が表示されることを確認し、明示操作なしに保存しない。
- PWAのHTTPS公開は2026-09-11に利用者承認を受けて実施済み。本番設定変更・実データ使用の追加承認とは扱わない。
- `target` 指定やURL起動だけでインストール済みPWAが開くことは保証しない。作成先の保存領域と操作性を実機で確認する。

## 5. ローカル実装と実機で残る確認

- ローカル実装準備版: `mvp-1.29.0`。端末保存schemaVersionは11、起動URLのschemaVersionは1。提供済み正式SVGと「連携済」を使用する。
- 自動試験: 合成データをブラウザ内で受け止める。URLフラグメントを含む `page.url()` から契約を検査し、外部サービスでは保存しない。詳細な品質ゲートは [リリース記録](releases/mvp-1.28.0.md) を参照。
- Android: 両PWA起動中／受信側終了時、起動先、保存後に普段のテンパリストをホーム画面から開いた時の同一リスト、同じURLでの再試行による既存リスト再利用を確認する。
- iOS/iPadOS: 通常ブラウザ内に限定する。ホーム画面版で連携が無効になること、ブラウザ版で同じ保存先へ受け渡せることを修正版の公開後に確認する。OS版・ブラウザ版と操作数も記録する。
- 相手側に未保存入力がある場合の中断と再試行、あとキューへ戻った際の表示も記録する。「連携済」は開く操作の受付履歴であり、受信・保存成功を保証しない。
- 320px表示・キーボード操作のブラウザ試験はOSのPWA捕捉・ソフトキーボード・保存領域の実機証跡にはならない。
- 状態は「PWA 1.28.0公開済み」「1.29.0ローカル準備中」「アイコン受領済み」「修正版の実機確認待ち」を分けて管理する。公開のSHA・CI・ブラウザ確認は [1.28.0リリース記録](releases/mvp-1.28.0.md)、今回の変更と検証は [1.29.0記録](releases/mvp-1.29.0.md) を参照。今回API再起動、テンパリストrepoへの書込は行っていない。
