# mvp-1.23.0 検証記録

## 原因と修正

- `mvp-1.17.0`で、既存の受信箱系列がある場合に新規未整理の予約計算自体を省略する条件が追加されていた。このため、初回通知済み後に新しい記録を追加しても初回通知が作られず、初回通知前の追加も後の時刻へ集約されなかった。
- 受信箱系列の起点を最新の未整理作成時刻へ戻し、新規追加時は常に系列を再計算する。同じ起点・設定なら既存seriesKeyで無変更維持し、時刻が変わる場合だけ旧系列を取消して最新の保存時刻＋設定時間から作り直す。
- 起動時の欠損補完が期限超過Taskだけに限定されていた。未整理・メモのscope全体、対応中Taskの不足kindをOutbox送信前に補い、既存kind・予約ID・送信待ちは維持する共通処理へ拡張した。
- 起動補完は保存直前に最新snapshotから再計算し、起動とオンライン復帰を直列化する。補完処理と同時に保存された記録・Taskを古いsnapshotで上書きしない。
- オフライン中に初回時刻を過ぎてAPIから拒否された未整理通知は、同じ復帰処理内で現在時刻へ再予約して1回だけ再送する。再送も失敗した場合はOutboxへ残し、無限再試行しない。
- 通知API項目、DB形式、保存schemaVersion、通知文面は変更しない。タスク本文・記録本文・局所IDを通知バックエンドへ送らない。
