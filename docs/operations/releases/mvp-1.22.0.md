# mvp-1.22.0 検証記録

確認日: 2026-08-31

対象要件: F-014、F-018、NF-002、NF-006、NF-009

## 原因と修正

- 全体通知系列の同一判定に送信待ちOutboxを使っていたため、登録成功でOutboxが空になると同じ系列でも取消・現在時刻での再登録が発生した。端末内の対応表へseriesKeyを保存し、無変更なら予約を保持する。
- APIが予定時刻の検証を冪等性照合より先に行っていたため、成功応答を受信できなかった予約の後日再送がINVALID_SCHEDULEとなり、端末が即時通知を再作成した。照合を先に行い、登録済み再送では元の応答だけを返す。
- 未登録の過去枠の復旧は当該枠だけに限定。単発枠は破棄、繰り返し枠は元の間隔の次の未来時刻へ進める。既存系列の起点変更でも過去の節目を現在時刻で再通知しない。
- 通知再設定は明示的な復旧操作として受信箱・メモ両系列を再登録する。通常起動や無変更保存では再登録しない。
- 保存形式v9→v10で既存予約・利用者データを維持。通知頻度の設定値、本文の保存境界、API項目、DBスキーマ、UI外観は変更しない。

## 調査の範囲

- 未整理2件・メモ0件のテストデータで、実API・Dispatcherを使い成功応答消失後に通知が2回発生することを再現。修正後は1回だけとなり再送Outboxも空になる。
- 本番の匿名予約情報では、短時間に取消・現在時刻での再登録・配送が繰り返されていた。ただし端末のローカル状態や実際の通信断は直接取得しておらず、利用者端末の各起動を引き金として確定したわけではない。
- 診断で本番の予約や利用者データを変更せず、実Pushを送るテストも行っていない。
