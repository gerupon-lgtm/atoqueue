### 通知時刻設定の追補（2026-08-08）

| 項目             | 決定・実装                                                                                                                                                                                                               |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 初回通知         | 【確定】記録の保存からの分数を端末全体で設定する。初期値60分。                                                                                                                                                           |
| 期限との境界     | 【2026-08-09に更新】期限ありタスクでは初回通知が期限より前の場合だけ予約する。同時刻・期限後は初回予約を省略し、期限時通知を残す。期限・設定変更時は不要になった既存初回予約を取消す。期限なし・期限未設定は従来どおり。 |
| 通知対象         | 【2026-08-09に更新】未整理の受信箱とメモ一覧は各一つの匿名全体系列を持ち、最古記録を基準にする。状態変更時は残件に応じて系列を再計算し、空になった系列だけを取消す。タスク化時はタスク用の予約へ置き換える。             |
| 期限前通知       | 【確定】期限ありタスクは、期限前の分数を端末全体で設定する。初期値60分。                                                                                                                                                 |
| 期限時通知       | 【確定】既存の再確認予約を期限時に使う。                                                                                                                                                                                 |
| 完了・アーカイブ | 【確定】対象タスクに紐づく匿名予約を全件取消する。                                                                                                                                                                       |
| 配送先読み       | 【確定】APIは`DEADLINE_DELIVERY_LEAD_SECONDS`（初期300秒）先までclaimして、期限前配送を試行する。                                                                                                                        |
| 同時刻の予約     | 【想定】過剰通知の試用結果を見て集約方針を決める。                                                                                                                                                                       |

### 受信箱再通知・メモ棚卸し・入力導線の追補（2026-08-09）

- 【実装済み】保存スキーマをv7へ移行し、受信箱再通知（`none` / `gentle` / `prompt`）、メモ棚卸し（`none` / `weekly` / `monthly`）、Enter登録の端末設定を追加した。既存端末の頻度は `none`、新規端末の初期値は受信箱 `gentle`、メモ `weekly`、Enter登録ONとする。
- 【実装済み】未整理の受信箱と `note` のメモは、それぞれ匿名の全体予約系列を一つだけ持つ。最古記録を基準とし、新規追加で時刻をリセットせず、全件解消時に取消す。週次・月次の繰り返しは配送成功後にサーバー側で次回へ進める。タスク本文、記録本文、期限、カテゴリ、局所IDはAPI・DB・ログ・Push payloadへ送らない。

### 端末入力・通知案内の追補（2026-08-08）

- 【確定】期限日は8桁数字（`YYYYMMDD`）、時刻は時刻有効化後に4桁数字（`HHMM`）で入力でき、カレンダー・時計ピッカーも併用する。これらのテキスト欄はタップ時に全選択する。
- 【確定】日付のみの期限は端末設定の既定期限時刻を使う。既定は23:59で、保存形式の `schemaVersion 4` は `5`、`5` は受信箱リマインド対応の `6`、`6` は全体再通知・メモ棚卸し・Enter登録対応の `7` へ移行する。
- 【確定】通知を受けるには利用者が「通知を設定する」を一度押して、ブラウザ許可・Push購読・匿名端末登録を完了する必要がある。
- 【確定】Android通知履歴に表示される「タップすると、このアプリのURLがコピーされます」はChromeのPWA管理通知であり、あとキューのリマインド通知ではない。
- 【確定】端末データ削除は二段階確認を通す。先に匿名Push端末登録をサーバー側で無効化できた場合だけ、ローカルの `atoqueue:data:v1` と下書きを削除する。他サイトの保存データには触れない。通信に失敗した場合はローカルの認証情報を残して再試行できるようにする。

## 5. リリースゲート

- すべての必須機能要件F-001〜F-017に成功する受入シナリオがある。
- `localStorage`を消さない限り、更新・オフライン・API停止でタスク本文を失わない。
- APIリクエスト、DB、ログ、Push payloadにタスク本文が存在しない。
- 通知不達でもアプリ起動時に同じ処理対象が表示される。
- iOS Home Screen PWA、Android Chrome、PC Chrome/Edgeの実機確認結果を記録する。
- JSONバックアップから別のブラウザプロファイルへ復元できる。
- 既知の【要確認】事項をリリース判断表へ移し、採用・延期・却下を明示する。
